# 文档之间的引用

`[文本](路径)` 是**文档链接**，`![[路径]]` 是**文档嵌入**（把目标正文并入当前文档），
`![alt](路径)` 是**媒体**。**`![]()` 不是文档引用形式**——反向索引和自动修链不遍历 image
节点，这样写的引用两边都看不见。

## 四种路径形式

当前文档在知识库「技术笔记」的 `/fa/da.md`：

| 形式 | 写法 | `[]()` | `![[]]` |
|------|------|--------|---------|
| **库根相对**（库内规范形式） | `/fa/db.md` | ✅ | ✅ |
| **文档相对**（基准 = 引用者所在文件夹） | 显式 `./db.md`、`../fb/dc.md`；裸 `db.md` | ✅ | ✅ |
| **库限定**（跨库） | `@产品手册/fb/dc.md` | ✅ | ❌ |
| **UID** | `/memos/abc123` | ✅ | ✅ |

- **跨库嵌入不支持**：嵌入内容会随宿主文档被分享/发布带出去，是刻意的非目标。
- **跨库路径不能带 `..`**：`@库标题/` 后面只接该库的库根相对路径。
- **库标题不含 `/`、不以 `@` 开头**（建库/改名时会被拒绝），匹配大小写不敏感。
- **路径里的空格必须百分号编码**：`[x](/笔记/Long Report)` 根本不会被解析成链接（目标在第一个
  空格处截断，剩下的漏成正文），要写 `[x](/笔记/Long%20Report)`。中文不用编码，保持可读。

## 规则

1. **库内默认写库根相对**，自动修链依赖它。跨库写库限定。
2. **别把已有的相对路径归一化**成库根相对——保存时系统不改写，你改了只是制造噪音 diff。
3. **别主动写 UID**。它只是"复制链接"的产物和机器降级目标，人读不懂。
4. **别去"修" `example.com/page` 这种裸路径**：裸相对解析不到会退回站外链接语义（不标坏链），
   它多半本来就是站外链接。要严格的坏链提示就写显式的 `./db.md`。
5. **移动文档会把它正文里的相对链接固化成库根相对**（按移动前的位置解析）。系统自己做，
   别手工模拟这套改写。库改名时库限定路径的库段同理。
6. **附件是 uid 寻址**（`/file/attachments/{uid}/…`），跨库天然可用：不要写 `@库/图.png`，
   也不要改写内联附件引用（见 `attachments.md`）。
7. **看到不可点击的受限链接，先核对库名再下结论。** 「库不存在」与「无权访问」刻意不可区分
   （可区分就等于给出库名探测接口），所以库名拼错和真的没权限长得一模一样。库名对但路径错
   是普通坏链，不是受限态。改之前先确认是哪一种，别把没权限的链接「修」掉。
