# 备份与对象存储

ToucanShelf 可以把数据库定期快照上传到 S3（或任何 S3 兼容的对象存储，如 MinIO、R2），
附件图片也可以直接存在同一个 bucket 里。

本文说明如何配置，以及**一条必须理解的安全前提**。

## 安全前提：备份文件等同于你的账号

请先读这一节再配置。

数据库快照是整个实例的完整副本。它里面包含：

- 所有文档内容
- **个人访问令牌（PAT）** —— 明文
- **第三方登录（OAuth/SSO）的 client secret** —— 明文
- 如果你是通过界面配置的 S3，还包含 **S3 的 Access Key** —— 明文

也就是说：**拿到一个备份文件的人，等同于拿到了你的整个实例。**

这不是可以通过「导出时清洗敏感字段」解决的问题——密钥散落在多张表里，清洗不干净，
而清洗干净了备份也就无法用于恢复。**请直接按「备份文件 = 账号本身」来对待它。**

具体来说：

- **不要**把备份文件分享给别人，哪怕只是让对方"看一下数据"
- **不要**把它放进任何会自动同步的目录（iCloud、Dropbox、OneDrive、公开的 Git 仓库）
- 恢复完成后，删掉临时下载到本地的备份文件

## 两条必做的配置

### 1. bucket 必须是私有的

新建 bucket 时**不要**开启公开读取。AWS S3 默认就是私有的，保持默认即可；
MinIO / R2 等请确认 bucket policy 不含匿名读权限。

配置完成后建议实测一次：把备份对象的 URL 直接贴进浏览器无痕窗口，
**应该返回 403 而不是开始下载**。

### 2. Access Key 只授权这一个 bucket

这是收益最高的一步。很多人图省事直接用账号的全权限密钥，那样一旦备份泄露，
丢的就不只是这个 bucket，而是整个云账号。

创建一个专用的 IAM 用户，只给它这一个 bucket 的权限：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::your-bucket"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::your-bucket/*"
    }
  ]
}
```

把 `your-bucket` 换成你的 bucket 名。MinIO 支持同样格式的策略。

做完这两步之后，风险就回到可接受范围：备份文件里的密钥只能访问它自己所在的那个
bucket，而能读到备份文件的人本来就已经在这个 bucket 里了。

## 配置方式

### 服务器部署（Docker 等）

在设置 → 存储 里填写 S3 配置，在设置 → 备份 里配置备份路径模板。

凭证会保存在数据库中——这正是上面「备份文件包含 S3 密钥」的来源。请务必完成
前述两条配置。

### 本地单机部署（standalone）

凭证通过**环境变量**提供，不写入数据库：

```
TOUCAN_S3_ENDPOINT=...
TOUCAN_S3_REGION=...
TOUCAN_S3_BUCKET=...
TOUCAN_S3_ACCESS_KEY_ID=...
TOUCAN_S3_ACCESS_KEY_SECRET=...
```

这样备份快照里不含 S3 密钥（PAT 和 SSO 密钥仍然在，前述安全前提依旧适用）。

这么设计不只是为了安全——**恢复的时候数据库还不存在**，凭证必须来自数据库之外，
否则无法启动。

环境变量存在时优先于界面配置。

## 备份路径模板

默认模板：

```
backups/{timestamp}_{uuid}.db.gz
```

支持的占位符：`{timestamp}` `{uuid}` `{year}` `{month}` `{day}` `{hour}` `{minute}` `{second}`

每次备份生成一个新对象，**不会覆盖旧的**。清理旧备份请用 bucket 自身的生命周期规则
（例如「30 天后自动删除」），ToucanShelf 不做保留策略管理。

## 已知限制

- 备份**只包含数据库**，不含附件文件本身。附件如果存在本地磁盘，需要另行备份；
  存在 S3 的则本身已在 bucket 中。
- 只有 SQLite 实例支持此功能。MySQL / PostgreSQL 请使用各自的备份工具。
- **同一份 S3 备份路径只能被一个实例使用。** 多个实例同时运行会互相覆盖，且是静默的
  数据丢失，没有任何报错。程序不做检测，请自行保证。
