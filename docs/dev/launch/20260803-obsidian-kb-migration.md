# Obsidian 知识库迁移上线记录

从一份真实的 Obsidian 知识库（AI 课程笔记，源库
`~/Workspace/jimmy-pink/jimmy-zhz.github.io/AI-Knowledge-Base`）迁移进 ToucanShelf 的
`AI_Handbook` workspace 的实际执行记录。方案见
[docs/dev/design/20260803-obsidian-kb-migration/](../design/20260803-obsidian-kb-migration/)。

脚本已开发完成并对真实源库全链路空跑通过，Python 3 标准库实现（无 `requests` 依赖），
对拍测试另需 `node`。

## 对拍测试的做法

平台标题锚点算法（slug）用 Python 复刻了一份，但没有"照着 TS 再写一份"就完事——那等
于自己跟自己比。测试直接从
[markdown-manipulation.ts](../../../web/src/utils/markdown-manipulation.ts) 原文里切出
`slugify` / `shortHash` / `headingSlug` 三个函数，剥掉类型标注后交给 node 执行。源实现
一旦改名或换签名，切片会失败报错，而不是悄悄比对一份过期副本。

语料是源库全部真实标题（含章节编号、emoji、括号、中英混排）加 20 个边界用例（纯
emoji、星平面字符、多空格、首尾连字符）。`encodeURIComponent` 的括号转义也单独跟
node 对过。

## 执行中改掉的方案内容

### 附件没有 workspace 字段

方案原计划以 `CreateAttachment(memo=该篇uid, workspace=目标ws, ...)` 的方式携带
workspace，但 `Attachment` 消息里根本没有 workspace 字段——附件归属哪个 workspace
完全由 `memo` 反推（blob 继承该 memo 所在 workspace 的存储目录）。这把"文档先行"从
一个权限上的考虑，升级成了硬约束：不带 memo 传上去，附件连该落哪个存储前缀都定不了，
上传顺序不能变。

### 用 attachment_id 做幂等

`CreateAttachmentRequest.attachment_id` 可由客户端指定，`attachment.uid` 在库里有唯一
约束，因此幂等有两道保险，而不是只靠本地清单：

1. 本地 `uploads.json` 清单，每上传一个立刻原子落盘；
2. attachment id = `kbmig-<sha256(文档路径+图片路径)[:24]>`。即便清单丢了、或者中断
   恰好发生在"服务端已建好、清单还没落盘"之间，重跑时重复创建会撞唯一约束，脚本转而
   `GetAttachment` 认回来，不会产生第二份附件。

### 裸 HTML 标题不参与锚点计算（有意偏离平台实际行为）

源库几乎每篇的大标题都写成 `<h1 style="...">标题</h1>` 而非 `# 标题`。平台的
`rehype-heading-id` 会给 hast 里的 h1–h6 一律赋 id，包括 HTML 写的那些，严格模拟本应
把它们算进锚点体系。**决定不算**——把"标题"永久绑在一段样式 HTML 上不是想要的形态，
迁移后由作者把那些 `<h1 style=...>` 改回 `# 标题`。实测这个决定不影响任何数字，因为
所有内链指向的都是 `##` / `###` 章节，没有一条指向文档大标题。

### 源库自带的存量死链：只报告，不改

源库里已存在 7 处标准 markdown 目录链接在平台 slug 规则下指不中（大小写、括号、小数
点、编号后缀等原因），不经任何转换直接迁入，只进复核报告交作者处理。脚本保留了
`--fix-anchors` 开关（默认关闭），可修正其中目标唯一确定的部分。

### 代码块里的假内链

源库 Python 代码块里的 `[[ '列1','列2' ]]`、`[[1,3,5]]` 等字面量，若不加保护会被正则
当成 Obsidian 内链改写掉。所有替换先算出保护区（围栏代码块、行内代码、`$`/`$$` 数学
公式、HTML 注释）再跳过落在其中的匹配；101 处 `[[...]]` 里有 3 处属于这种，已正确
跳过，内链统计因此是 98 处而不是 101 处。

### dry-run 与实跑必须用独立清单文件

早期版本 dry-run 和实跑共用 `uploads.json`，会导致紧接着的实跑误判为"一切已完成"而
不传任何附件，正文里全是不存在的 uid。改为 dry-run 单独写 `uploads.dryrun.json`。

## 执行前置条件

1. S3 附件按 workspace 分目录的能力必须已部署（否则附件会落进旧的公共前缀，迁完还得
   再搬一次）。
2. 目标 workspace 需已在 web 端建好。

工作目录刻意放在 memogit checkout 根目录之外：memogit 的 `listDocFiles` 只跳过
`_attachments/`、点开头文件和冲突 sidecar，其余一切都当文档处理，图片一旦进了内容树
会变成"正文是二进制乱码的文档"。`stage` 步骤对此有硬校验，发现非 `.md` 文件直接中止。

## 复核报告要看什么

`migrate.py report` 产出的报告里，以下几类条目属预期内、不是迁移故障：锚点匹配不上
已降级（7）、内链目标文档找不到（3，含 2 篇本就不迁移的文档和 1 处命名不对应）、源库
自带 `](#anchor)` 指不中（7，存量问题原样迁入）。需要人工确认的：靠模糊匹配救回的锚点
（2，需抽查确实指对）、被剥壳的 HTML（17 处/4 篇，需扫一眼文本没黏成一行）。图片引用
找不到文件、图片 basename 重名这两项预期为 0，出现非零即真问题。

## 遗留事项

- 20 个未被任何文档引用的图片不上传。
- 裸 HTML 大标题的后续整改、以及 7 处存量死链的修复，由作者在迁移完成后自行处理。
- 迁移完成后需手动把该 workspace 的换行设置改成 soft break——源库是 CommonMark 语义，
  平台默认 `remark-breaks` 会把每个换行都变成 `<br>`，不改会让段落排版变形；这一步
  按约定不写进脚本，也不动实例级默认值。
