# 对外发布（Publish）上线

需求见 [../requirements/20260823-public-blog-publishing.md](../requirements/20260823-public-blog-publishing.md)，
技术方案见 [../design/20260823-public-publishing/tech-design.md](../design/20260823-public-publishing/tech-design.md)。

本篇是上线执行本身：上线前准备什么、按什么顺序操作、上线过程盯什么、
上线后满足什么条件才算完成，以及上线之后怎么验证需求真的被满足了。

按 [tech-design §7](../design/20260823-public-publishing/tech-design.md) 的分阶段，
P0～P4 各走一次本篇的流程；下面的清单里标了 `[P0]` 的是首次上线必须做完的，
其余在对应阶段补。

## 一、前置准备

**数据与备份**

- [ ] `[P0]` 上线前做一次全站 SQLite 备份，并**实际验证能恢复**（见
      [backup.md](../requirements/storage/backup.md)），不是只确认备份文件存在。
- [ ] `[P0]` 新表迁移脚本在**生产库的一份拷贝**上先跑一遍，记录耗时。
      本次只新增表、不改 `memo` 表结构，回滚等价于删表。

**配置与依赖**

- [ ] `[P0]` 确认对外路由不依赖实例的 `AllowAnonymous`（该开关现在等价于
      "配了 InstanceURL"）。站点可访问性只由站点自身的 `status` 决定。
- [ ] `[P3]` 确认 embedding provider 已配置；没配也必须能上线，站点搜索
      降级为纯关键词。
- [ ] `[P4]` 域名 CNAME 已解析到本实例、归属校验通过、证书签发链路走通。

**内容与人**

- [ ] `[P0]` 先建一个**测试站点**，用真实文档走完一遍发布，确认 §四 的验收项
      全绿之后，再建正式站点。
- [ ] `[P0]` 准备好首发内容清单：哪几篇文章、发到哪个站点，以及每篇引用到的
      文档和附件是否都已就绪。
- [ ] `[P2]` dashboard 那篇 `.view` 文档已经编排好并能正常预览。

**开关与回滚**

- [ ] `[P0]` 整块能力有一个实例级开关，关掉之后对外路由整体 404，
      不依赖删数据。
- [ ] `[P0]` 回滚方案写清楚：关开关 → 站点 `status` 置 `OFFLINE` →
      必要时删新表。确认回滚不影响知识库内部功能。

## 二、实操步骤

按顺序执行，每步做完确认再进下一步。

1. 停写窗口不需要——本次不改存量表。直接部署新版本。
2. 跑迁移，确认新表建出来、老功能（打开文档、搜索、memogit sync）正常。
3. 保持实例级开关**关闭**，先在后台建测试站点，`status = DRAFT`。
4. 打开开关，把测试站点置 `ONLINE`，走平台路径访问（先不绑域名）。
5. 发布 1 篇不含附件、不含引用的简单文档，确认页面出得来。
6. 发布 1 篇**带附件 + 带站内引用 + 带加密块**的文档，逐项对照 §五 验收。
   附件那条重点看"发布前后 access 没变"。
7. 测试站点验收通过后，建正式站点、发布首发内容清单里的文章。
8. `[P4]` 绑定域名，验证 canonical 与 301，提交 sitemap。
9. 测试站点置 `OFFLINE` 并删除，避免留一个半成品站点在外面。

## 三、重点盯盘

上线后 24 小时内重点看这几项，任一项异常就先关开关再排查：

- **越权与泄露**：对外接口的访问日志里，有没有出现查询 `memo` 表的路径；
  匿名请求 `SecretBlockService` 是否被拒；未发布文档的 slug / doc-id 探测
  是否稳定 404。
- **附件权限**：发布前后附件的 access 有没有任何变化——**应该一条都没有**。
  发布不碰附件权限，出现变化就说明有代码绕过了这条边界。
- **主应用性能**：对外流量进来之后，内部使用的响应时间、SQLite 的锁等待、
  慢查询有没有变化。这是快照模型本该保护住的地方，一旦变差说明有对外请求
  绕回了文档表。
- **发布失败率**：引用检查导致的发布失败是否集中在同一类原因上——如果作者
  普遍卡在同一处，说明检查提示写得不够清楚，而不是作者的问题。
- `[P4]` **证书与域名**：签发是否成功、有没有异常的按 Host 签发请求。

## 四、后置条件（满足才算这次上线完成）

- [ ] 测试站点已删除，线上只留正式站点。
- [ ] 首发内容清单里的每篇文章都能在站点上正常打开，且**内容与知识库里
      当前版本一致**（首发时两者应当没有差异）。
- [ ] 关掉实例开关能让整站 404，打开能恢复——回滚路径实际验证过，不是纸面上的。
- [ ] 本次上线过程中改掉的方案内容，回写到 tech-design；改掉的产品结论，
      回写到需求文档。
- [ ] [roadmap.md](../roadmap.md) 里"对外发布"那条按实际进度更新。

## 五、上线后的需求验证标准

逐条对照需求文档验收。**这些都是人工执行的检查项**，每条都写明了怎么验、
看到什么算通过。

### 快照语义（需求 §5）

- [ ] 发布一篇文章后，在知识库里改正文并保存，**不点更新发布**：站点上的页面
      内容不变。
- [ ] 点"更新发布"之后，站点上的内容变成新版本。
- [ ] 改完还没更新发布时，编辑器里能看到"线上版本落后于当前版本"的提示。
- [ ] 用 memogit push 或 MCP 改一篇已发布文档：站点内容同样不变，且提示出现。

### 安全边界（需求 §9）

- [ ] 文章里引用一篇**未发布到本站点**的文档 → 发布被拒，且错误信息里点名了是
      哪几条引用。
- [ ] 文章里含**私密附件** → 发布被拒。
- [ ] 文章里含**加密块** → 发布成功，但对外页面上这个块整个不存在（查看页面
      源码确认没有块的痕迹），且匿名直接请求密文接口被拒。
- [ ] 文章里含普通未公开附件 → 发布**能过**，同时列出了"读者取不到"的附件清单；
      发布之后去数据库确认这些附件的 access **没有被改动**。作者自己把文件设成
      公开之后，页面上的图才显示得出来。
- [ ] 对外页面上看不到：评论、版本历史、内部 frontmatter 属性、memogit 身份
      标记、作者账号信息。
- [ ] 撤下一篇被别的已发布文章引用的文档 → 出现警告并列出受影响的页面。
- [ ] 撤下之后，附件权限同样没有任何变化（发布没放开过，撤下也就无从回收）。
- [ ] 把已发布文档丢进回收站 → 站点上等同撤下。

### 站点与跨库（需求 §3 §4）

- [ ] 把两个不同知识库的文档发到同一个站点，都能正常打开。
- [ ] 两个库里**同名**的文档发到同一个站点，slug 不冲突，各自能打开。
- [ ] 同一篇文档发到两个站点，两个站点上各有一条独立记录、各自的 slug，
      在其中一个站点撤下不影响另一个。
- [ ] 跨库汇聚之后，文章里的站内链接指向的是**正确那篇**文档（重点验同名路径）。
- [ ] 用 member 账号登录：看不到发布入口，直接调接口也发不出去。

### 首页与搜索（需求 §6 §7）

- [ ] dashboard 上只出现本站点已发布的文章；把一篇未发布文档放进 scope，
      它不出现。
- [ ] 新发一篇文章，**不重新发布 dashboard**，首页上立刻出现这一条。
- [ ] 改 dashboard 版式但不点更新发布 → 线上版式不变（版式走快照，条目是活的）。
- [ ] 站点搜索能搜到已发布文章；搜一个只存在于**未更新发布的新正文**里的词，
      搜不到。
- [ ] 实例未配 embedding 时，站点搜索降级为关键词检索且仍然可用。

### URL 与 SEO（需求 §8 §10）

- [ ] `/<slug>` 能打开；改文章标题后 slug 不变。
- [ ] `/d/<doc-id>` 重定向到当前 slug；在**没发布这篇文档的另一个站点**上访问
      同一个 doc-id → 404。
- [ ] slug 手改成保留字（如搜索页路径）→ 被拒绝。
- [ ] `[P4]` 平台路径与自定义域名只有一个是 canonical，另一个 301 过去。
- [ ] `[P4]` sitemap 里只有已发布页面；撤下的页面返回 410。
- [ ] `[P4]` 站点 `status` 置 `OFFLINE` → 整站 404。
