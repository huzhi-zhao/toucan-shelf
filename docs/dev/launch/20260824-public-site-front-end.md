# 对外站点门面上线

需求见 [../requirements/public-site-front-end.md](../requirements/public-site-front-end.md)，
方案见 [../design/20260823-public-publishing/front-end.md](../design/20260823-public-publishing/front-end.md)。

发布能力本身（快照、检查、slug、按 Host 路由）的上线走
[20260823-public-publishing.md](20260823-public-publishing.md)，**那篇是本篇的前置**：
门面是发布出去的内容的呈现层，P0 没走完就没有内容可呈现。

本篇按方案 §9 的 P2a / P2b / P2c / P3 分四次走，每次都过一遍下面的流程；
标了阶段号的条目在对应阶段做完。

## 一、前置准备

**依赖**

- [ ] `[P2a]` 发布 P0 已上线，测试站点上至少有 3 篇已发布文章——**少于 3 篇看不出
      版式问题**，卡片墙和 feed 在一条数据下都是好看的。
- [ ] `[P2b]` 至少有 1 篇**带封面图**、1 篇**不带封面图**的已发布文章。
      没有封面的卡片必须自己成立，这是要实际看的，不是读代码能确认的。
- [ ] `[P2b]` dashboard 那篇 `.view` 已经编排好并能在库内正常预览。

**配置**

- [ ] `[P2a]` 主题白名单键定稿，且**服务端校验已经生效**——不是前端过滤。
      拿一个不在白名单里的键直接打接口，应当被拒。
- [ ] `[P2a]` 确认对外页面不再调用应用的主题初始化：切换应用主题、清空
      localStorage，站点外观都不应改变。

**回滚**

- [ ] `[P2a]` 回滚就是把对外路由切回换皮之前的组件。确认新旧两套之间**没有共享
      状态**，切回去不需要清数据。
- [ ] `[P2b]` dashboard 解析失败时首页降级成平铺 feed，而不是白屏——回滚之外
      还要有这条兜底，因为它挡的是内容问题，不是代码问题。

## 二、实操步骤

1. 部署新版本，确认库内功能（打开文档、gallery view、Explore）没有变化——
   门面是新增组件树，不该影响库内任何东西。
2. `[P2a]` 在测试站点上依次打开首页、文章页、404 页，确认外壳一致。
3. `[P2a]` 配一份非默认主题，确认三个页面都跟着变。
4. `[P2b]` 发布 dashboard，确认首页从平铺 feed 变成编排后的样子。
5. `[P2b]` 故意把 dashboard 的块 JSON 改坏一个字段，确认首页降级而不是白屏，
   然后改回来。
6. `[P2c]` 配导航树，确认目录页；树里挂一篇未发布的文章，确认该项不渲染。
7. `[P3]` 打开搜索页，确认走的是站点索引而不是前端过滤。
8. 全部通过后，正式站点重复 2～7。
9. **删掉 `blog-preview` 路由、`BlogSite/previewFixtures.ts` 和 `BlogPreview.tsx`。**
   预览页是给这次评审用的脚手架，接上真实数据之后留着就是一份会腐烂的假内容。

## 三、重点盯盘

- **越权与泄露**：对外页面的网络请求里，**有没有出现 memo / workspace 接口**。
  这是本次最该盯的一项——门面是新增了一批组件，而这批组件是最容易顺手 import
  一个库内 hook 的地方。看请求，不看代码。
- **首页可用性**：dashboard 解析失败的降级有没有真的触发过；触发了就说明块 JSON
  的兜底还不够。
- **主题**：有没有非白名单的键被存进 `site.theme`。
- **封面**：有没有卡片的封面图 403 / 404。有就说明附件权限那条清单没被作者处理，
  属于提示不够，不是读者的问题。
- **首屏**：对外页面的加载时间。皮肤是新增的一个 lazy chunk，不该把首屏拖长。

## 四、后置条件（满足才算完成）

- [ ] 预览路由与 fixture 已从代码里删除。
- [ ] 正式站点的首页、文章页、目录页、搜索页都能打开，且四个页面的外壳一致。
- [ ] 主题改一次，四个页面同时跟着变。
- [ ] 本次改掉的方案内容回写到 front-end.md，改掉的产品结论回写到需求文档。
- [ ] [roadmap.md](../roadmap.md) 里"对外发布"那条按实际进度更新。

## 五、上线后的需求验证标准

人工执行，每条写明怎么验、看到什么算通过。

### 分层（需求 §1）

- [ ] 顶部菜单和导航树在**文章页、搜索页、目录页**上都在——不只是首页。
- [ ] 把 dashboard 那篇 `.view` 撤下发布：首页降级，但文章页的外壳**不受影响**。
      外壳如果跟着没了，说明它被塞进了 `.view`。

### 导航树（需求 §3）

- [ ] 树里挂一篇未发布到本站点的文章 → 该项不渲染，且不是死链。
- [ ] 一篇文章同时挂在两节里 → 两处都能点开，URL 是同一个 `/<slug>`。
- [ ] 一篇文章不挂在树上 → 仍能被搜索和 feed 找到。
- [ ] 树上任何一项的 URL 都不带层级路径（不出现 `/docs/getting-started` 这种）。

### 首页编排（需求 §4）

- [ ] 把首页的块顺序改成「feed 在前、gallery 在后」→ 页面跟着变，且**不需要改
      任何代码**。
- [ ] 一个 gallery 块配 tags 筛选 → 只出现带这些 tag 的文章。
- [ ] 把一篇**未发布**的文档放进任意块的范围 → 它不出现。
- [ ] 新发一篇文章，**不重新发布 dashboard** → 首页 feed 里立刻出现。
- [ ] 改 dashboard 版式但不点更新发布 → 线上版式不变。
- [ ] 对外块的配置表单里**没有**文件夹和属性两种筛选项。

### 皮肤与主题（需求 §5 §6）

- [ ] 在应用里切换主题 / 深色模式 / 清空 localStorage → 站点外观**一点都不变**。
- [ ] 改站点主题的配色和字体 → 首页、卡片、文章正文**同时**跟着变
      （正文也变，才说明变量映射做对了）。
- [ ] 往 `theme` 里塞一段 CSS 或 HTML → 被服务端拒绝。
- [ ] 库内 gallery view 的卡片密度**没有**因为这次改动而变化。

### 正文渲染（需求 §7）

- [ ] 一篇含 sheets / calendar / draw.io 块的文章发布后，站点上渲染正常，
      且与库内看到的一致。
- [ ] 含加密块的文章：站点页面源码里**没有**那个块的任何痕迹。

### 封面（需求 §8）

- [ ] 有 frontmatter 封面属性的 → 用它；只有正文首图的 → 用首图；两者都没有的
      → 卡片没有图片位但排版仍然成立。
- [ ] 发布之后把源文档里的封面图换掉、**不点更新发布** → 站点卡片的封面不变。
- [ ] 封面指向一个未公开附件 → 发布能过，且"读者取不到"清单里列出了它；
      数据库里那个附件的 access **没有被改动**。

### 语言（需求 §9）

- [ ] 把浏览器语言切成中文访问站点 → 界面文案仍然是英文。
- [ ] 一篇中文文章在站点上渲染正常：行高、标点、换行都没崩。
