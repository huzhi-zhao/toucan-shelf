# 对外站点门面上线

需求见 [../requirements/public-site-front-end.md](../requirements/public-site-front-end.md)，
方案见 [../design/20260823-public-publishing/front-end.md](../design/20260823-public-publishing/front-end.md)。

发布能力本身（快照、检查、slug、按 Host 路由）的上线走
[20260823-public-publishing.md](20260823-public-publishing.md)，**那篇是本篇的前置**：
门面是发布出去的内容的呈现层，P0 没走完就没有内容可呈现。

本篇按方案 §9 的 P2a / P2b / P2c / P3 分阶段走，外加 P4 的 SEO 那半。
**当前状态：P2a / P2b / P2c / P3 / P4-SEO 代码已合并、静态检查全绿，尚未上线
验收；P4 的自定义域名那半未开工。** 所以这一次上线是这五段**一起**验，下面标
`[P2a]` / `[P2b]` / `[P2c]` / `[P3]` / `[P4-SEO]` 的条目本次都要过。

P3 落的是**最小实现**：搜索在服务端对 `site_publication` 做 `LIKE` 子串匹配，
没有索引表也没有分词（见方案 §5）。所以验收要盯的是**范围对不对**（只搜本站点
已发布快照），不是**排序好不好**——子串匹配本来就没有相关性排序。

## 二、实操步骤

照着敲的版本（起实例、准备内容、逐条 curl）在
[20260824-public-site-local-walkthrough.md](20260824-public-site-local-walkthrough.md)，
本地第一遍建议直接跟那份走，这一节留作正式实例上的简表。

按顺序执行，每步做完确认再进下一步。**先在本地实例走完 2～10，全绿之后再部署
正式实例，然后在正式站点上重复 3～10。**

1. 部署新版本并跑迁移（`./deploy.sh`；本地是 `go run ./cmd/memos --port 8081`
   加 `cd web && pnpm dev`）。确认库内功能（打开文档、gallery view、Explore、
   memogit sync）没有变化——门面是新增组件树，不该影响库内任何东西。
2. 确认 `site` 表多了 `nav` 列，且存量站点的值是 `[]`：

   ```bash
   sqlite3 memos_prod.db "SELECT id, name, nav FROM site;"
   ```

3. `[P2a]` 打开站点首页、文章页、一个不存在的 slug（404 页），确认三个页面的
   外壳一致。
4. `[P2a]` 在**设置 → 站点**（`/setting#site`）配一份非默认主题，确认三个页面
   都跟着变，**且文章正文也跟着变**——正文变了才说明变量映射做对了。
5. `[P2b]` 在**设置 → 站点 → 首页**里把那篇 `.blogview` 选成首页（首页不走"发布"，
   在这里选中即冻结版式），确认首页从平铺 feed 变成编排后的样子。
6. `[P2b]` 验字段级兜底：把一个对外卡片墙的列数改成非法值（表单里填 `7`）或把
   排序设成"手动"却不填 slug，回到设置里重新保存首页，确认首页**照常渲染、
   该字段回落默认值**，
   而不是整块消失或白屏。然后改回来。
7. `[P2b]` 打开那篇带 frontmatter 的文章，看页面源码里**没有** `status` /
   `memogit-id` 这些库内字段。
8. `[P2c]` 在**设置 → 站点 → 导航树**配树（缩进按钮即嵌套），保存；再在**顶部
   菜单**里加一项，path 填 `contents`。
9. `[P2c]` 打开 `/contents`：树里那篇**未发布**的文章对应的项应当**整条不出现**
   ——不是灰掉，也不是死链。然后直接看接口，确认不是前端藏起来的：

   ```bash
   # siteUid 就是平台路径 /s/<siteUid> 里的那一段
   curl -s 'http://localhost:8081/api/v1/public/site?site=sites/<siteUid>' | jq .nav
   ```

10. 全部通过后，把测试站点 `status` 切回原状，正式站点重复 3～9。
11. `[P3]` 打开 `/search`，输入一个**只出现在某篇文章正文里、不在标题和摘要里**
    的词，确认能搜到——搜得到才说明搜的是快照正文，不是前端在 feed 上过滤。
    然后看网络请求，确认打的是 `pages:search`，且请求里带着 `q`。
12. `[P3]` 搜一个只在**未发布**文档里出现的词 → 没有结果。再搜一个词，它只在
    某篇已发布文章**发布之后新加的正文**里 → 也没有结果（快照没跟着编辑走）。
13. `[P3]` 搜索框里输入 `%` → 不是列出全站，而是"没有结果"。
14. `[P4-SEO]` 用 curl 看状态码，**不要用浏览器**——浏览器上三种情况长得一样：

    ```bash
    curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/s/<siteUid>/<已发布slug>
    curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/s/<siteUid>/<撤下的slug>
    curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/s/<siteUid>/never-was
    ```

    期望依次是 `200` / `410` / `404`。
15. `[P4-SEO]` `curl -s http://localhost:8081/s/<siteUid>/sitemap.xml`：只出现本
    站点已发布的 slug，**不出现** `/memos/`（那是应用自己的 public memo 列表，
    混进来就是把库内内容推给了爬虫）。
16. `[P4-SEO]` `curl -sI http://localhost:8081/s/<siteUid>/<已发布slug> | grep -i
    '^link:'`：canonical 指向 `site.canonical` 选中的那个入口。

## 三、重点盯盘

- **越权与泄露**：对外页面的网络请求里，**有没有出现 memo / workspace 接口**。
  这是本次最该盯的一项——门面是新增了一批组件，而这批组件是最容易顺手 import
  一个库内 hook 的地方。看请求，不看代码。
- **导航树的泄露面**：树是作者手写的，可能提前写好了还没发布的章节。要盯的不是
  "有没有死链"，而是**未发布项的标签有没有漏出去**——一项写着「薪酬制度」却点不动，
  标签本身就说明库里有这么一篇。裁剪在服务端做，所以这一条要看接口返回而不是页面。
- **首页可用性**：dashboard 解析失败的降级有没有真的触发过；触发了就说明块 JSON
  的兜底还不够。
- **主题**：有没有非白名单的键被存进 `site.theme`。
- **封面**：有没有卡片的封面图 403 / 404。有就说明附件权限那条清单没被作者处理，
  属于提示不够，不是读者的问题。
- **frontmatter**：对外页面源码里有没有残留库内字段。这条是 P2b 顺手补的漏，
  以前 frontmatter 是原样进快照的，只是碰巧没人渲染。
- **首屏**：对外页面的加载时间。皮肤是新增的一个 lazy chunk，不该把首屏拖长。

## 五、上线后的需求验证标准

人工执行，每条写明怎么验、看到什么算通过。

### 分层（需求 §1）

- [ ] 顶部菜单和导航树在**文章页、目录页**上都在——不只是首页。
- [ ] 在设置里把首页选回"所有已发布页面的信息流"：首页降级，但文章页的外壳
      **不受影响**。外壳如果跟着没了，说明它被塞进了 `.view`。

### 导航树（需求 §3）

- [ ] 树里挂一篇未发布到本站点的文章 → 该项不渲染，且不是死链；接口返回里也
      没有它的标签。
- [ ] 把那篇文章发布 → **不用改树**，目录页上该项自己出现。
- [ ] 再把它撤下 → 该项自己消失。
- [ ] 一个分组节点底下的文章全部未发布 → **整个分组不出现**（分组标签也是信息）。
- [ ] 一个既指向文章、底下又挂了未发布子项的节点 → 节点还在，子项没了。
- [ ] 一篇文章同时挂在两节里 → 两处都能点开，URL 是同一个 `/<slug>`。
- [ ] 一篇文章不挂在树上 → 仍能被 feed 和搜索找到。
- [ ] 树上任何一项的 URL 都不带层级路径（不出现 `/docs/getting-started` 这种）。
- [ ] 站点没配树时打开 `/contents` → 列出全部已发布文章，不是空白页。
- [ ] 拿接口直接塞一个绝对 URL 或 `javascript:` 当 nav 的 slug → 被服务端拒绝。

### 首页编排（需求 §4）

- [ ] 把首页的块顺序改成「feed 在前、gallery 在后」→ 页面跟着变，且**不需要改
      任何代码**。
- [ ] 一个 gallery 块配 tags 筛选 → 只出现带这些 tag 的文章。tag 的来源是文档
      frontmatter 的 `tags:` 列表：给一篇文章写上 `tags: [guide]` 重新发布 →
      它进 `guide` 块；把 tag 从 frontmatter 里删掉重新发布 → 它退出。
- [ ] 一篇文章正文里带 `#guide`、frontmatter 里**没有** `tags:` → 发布后它是
      无标签的，不进任何 tags 筛选块。正文 `#tag` 不是发布输入（见
      [roadmap](../roadmap.md) 的「正文 `#tag` 已暂停」，清除待办见根目录 [TODO.md](../../../TODO.md)）。
- [ ] 把一篇**未发布**的文档放进任意块的范围 → 它不出现。
- [ ] 新发一篇文章，**不重新保存首页** → 首页 feed 里立刻出现。
- [ ] 改 dashboard 版式但不回设置里重新保存 → 线上版式不变；重新保存后才变。
- [ ] 站点**没设首页** → 站点根是一个 Latest feed，列出全部已发布页面，带 tag 筛选。
- [ ] 把一篇只有 markdown / gallery、**没有 feed 块**的 `.blogview` 设为首页 → 被拒，
      报"必须包含至少一个 feed 块"；补上 feed 块后能设上。
- [ ] 「新建站点首页」建出来的文档**自带**一个 Latest feed 块。

### 归档页 `/archive`

- [ ] 新建站点的顶部菜单是 `Home` / `Archive` / `Search`，Archive 点进去列出**全部**
      已发布页面。**已有站点不受影响**（菜单是作者数据），要在站点设置里自己加
      一条 label `Archive`、path `archive`。
- [ ] 发布**超过 50 篇**（服务端默认页大小）→ 归档页先显示 50 条并出现「Load more」，
      点一次再来一批，点到没有为止；**首页的 feed 不会**列出全部，它是被裁剪过的门面。
- [ ] 归档页按年份分组，年份倒序；没有日期的进 "Undated" 分组而不是被丢掉。
- [ ] 归档页的 tag 筛选只在**已加载**的条目上生效——筛完还有 Load more 就说明可能还有。
- [ ] `/archive` 出现在 `sitemap.xml` 里；`archive` 不能被拿去当文章 slug（发布时被拒）。
- [ ] 首页 feed 底部有「See every post」，点进归档页。
- [ ] dashboard 那篇 `.blogview` 的文档页上**没有发布按钮**；直接调 `PublishMemo`
      发它 → 被服务端拒绝。`.view` 同样发不出去。
- [ ] 首页那篇 `.blogview` **不出现在**文章列表、目录页和 `/<slug>` 里——它不是页面。
- [ ] 手改 `.blogview` 的 JSON，塞一个**库内** gallery / calendar 块（scope 里写上
      文件夹和 frontmatter 属性），保存首页 → 打开首页接口的**响应体原文**搜那个
      文件夹名和属性名，一个都搜不到。要手改是因为编辑器已经不给库内块了；这条
      守的是手改和 memogit 这两条路，看的是响应体不是页面。
- [ ] 对外块的配置表单里**没有**文件夹和属性两种筛选项。
- [ ] `.blogview` 的插入菜单里**没有** gallery / calendar / 文档引用；`.view` 的插入
      菜单里**没有**对外卡片墙 / 对外列表。两边都还有附件上传。
- [ ] 站点设置的首页下拉里**只列 `.blogview`**；把一篇 `.view` 硬塞给
      `UpdateSite(dashboard)` → 被服务端拒绝。
- [ ] 在库内打开 dashboard 那篇 `.blogview` → 对外块画的是占位说明，不是真的把文章

### 皮肤与主题（需求 §5 §6）

- [ ] 在应用里切换主题 / 深色模式 / 清空 localStorage → 站点外观**一点都不变**。
- [ ] 改站点主题的配色和字体 → 首页、卡片、文章正文**同时**跟着变

### 正文渲染（需求 §7）

      且与库内看到的一致。
- [ ] 含加密块的文章：站点页面源码里**没有**那个块的任何痕迹。
- [ ] 一篇带 frontmatter 的文章：站点页面源码里**没有** frontmatter 的任何字段。

### 封面（需求 §8）

- [ ] 有 frontmatter 封面属性的 → 用它；只有正文首图的 → 用首图；两者都没有的
      → 卡片没有图片位但排版仍然成立。
- [ ] frontmatter 里写了封面、正文里另有首图 → 用 frontmatter 那张（顺序是
      frontmatter → 正文首图 → 空）。
- [ ] 发布之后把源文档里的封面图换掉、**不点更新发布** → 站点卡片的封面不变。
- [ ] 封面指向一个未公开附件 → 发布能过，且"读者取不到"清单里列出了它；
      数据库里那个附件的 access **没有被改动**。

### 搜索（需求 §1、发布篇 §7）

- [ ] 搜一个只在正文里出现的词 → 命中；说明搜的是快照正文。
- [ ] 搜一个只在未发布文档里出现的词 → 无结果。
- [ ] 一篇文章发布后在库内继续编辑，加一个新词 → 搜这个新词无结果，**且**打开
      文章页看到的还是旧正文。两条一起才说明快照语义是一致的。
- [ ] 搜两个词 → 只出现同时含这两个词的文章（是收窄不是放宽）。
- [ ] 中文站点搜一个中文词 → 能命中（整串子串匹配，不分词）。
- [ ] 站点菜单里删掉搜索项 → 顶部搜索入口消失；但**直接访问 `/search` 仍然
      打得开**，这是已知行为：菜单管的是入口，不是权限。
- [ ] 搜索页的网络请求里没有 memo / workspace 接口。

### SEO（需求 §10）

- [ ] 已发布文章 → `200`，响应头**没有** `X-Robots-Tag`。
- [ ] 把它撤下 → 同一个 URL 变成 `410` 且带 `X-Robots-Tag: noindex`。**这条是这
      半边的全部意义**：SPA 对任何 URL 都回 200，不做这一步的话撤下一篇文章之后
      爬虫看到的还是"200 + 客户端渲染的找不到"，文章会一直留在搜索结果里。
- [ ] 从没存在过的 slug → `404`（不是 410——410 是"曾经有、没了"）。
- [ ] 站点 sitemap 里没有未发布 / 已撤下的 slug，也没有应用自己的 memo。
- [ ] 把站点 `status` 切成 OFFLINE → 它的 sitemap 不再列任何东西（站点在这一层
      根本解析不出来），与"这个站点不存在"一致。
- [ ] 站点绑了域名的话：`canonical` 设成 PLATFORM 时，域名上的 `robots.txt` 是
      `Disallow: /`，且页面的 `Link` 头指回平台路径；设成 DOMAIN 时反过来。
- [ ] 应用自己的 `/robots.txt` 和 `/sitemap.xml` **没有变化**（不在站点域名上访问
      时）。
