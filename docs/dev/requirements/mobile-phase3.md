## 2. 收藏阅读

写作时看到值得以后再读的文档，标一下收藏；闲下来时从手机书架翻出来读。

- **在哪里标**：两端都能标、都能取消（2026-10-18 改：原先只在 web 端）。
  - web：文档编辑页右上角菜单里的"收藏 / 取消收藏"。
  - 手机：阅读页右上角菜单里的"收藏 / 取消收藏"。
- **只能手动移走**：程序判断不了是不是真的读完了，所以读完也不会自动移出，由用户自己取消收藏。不做"已读"状态。
- **在哪里看**：手机书架页加一块"收藏"，像阅读列表：
  - 每行显示文档标题和所在知识库，点开进阅读页；
  - 先列钉住的，再列最近收藏的 5 篇（按收藏时间，最新的在前）；钉住的不占这 5 篇的名额；
  - 最后一个"全部"入口，进去是完整的收藏列表，同样钉住的在前、其余按收藏时间。
- **钉住**：有些收藏时间久了但很重要，钉住后一直显示在书架上。在收藏列表里钉住、取消钉住。
- **个人的**：每个用户只看到自己的收藏。文档自带的"置顶"（`pinned`，从 memos 继承）是所有人共用的，
  不拿来当收藏；收藏单独存一张表（用户、文档、收藏时间、是否钉住）。
- 文档被删除或者没有权限读了，就不在列表里显示。
- **位置**：收藏块放在书架的知识库下面。
- **实现**（2026-10-18）：
  - 表 `memo_favorite`（迁移 `0.30/26__memo_favorite.sql`），接口 `FavoriteService`（`/api/v1/favorites`）：列出、添加、钉住、取消。
  - 列出时：文档已删除的收藏顺手清掉；在回收站、所在知识库被隐藏、或者没有权限读的，只是不显示，文档恢复后又会出现。
  - web：文档页右上角"⋮"菜单里的"收藏 / 取消收藏"。手机：阅读页右上角的星标。
  - 手机书架的"收藏"块显示钉住的加最近 5 篇；超出时右上角"全部 N 篇"进完整列表（`/favorites`），每行右边的图钉切换钉住。

## 3. 知识库待办预览

知识库文档里的 `- [ ]` 现在只能一篇篇打开看，想在手机上一眼看到"知识库里还挂着哪些事"。

- **和计划的待办是两回事**（2026-10-18 定）：不搬进计划，不互相同步，也不做"加入计划"。
  原先考虑的几种做法（只读汇总、整批转成计划待办、约定推送）都先不做，先按下面这样上线看效果。
- **只看根目录的 TODO 文档**（2026-10-18 改）：每个知识库根目录下名为 `TODO` 的那篇文档，才是写给人看的待办。
  知识库里其他文档里的 `[ ]` 多是写给 agent 的工作清单，不列。第一版把所有文档都翻了一遍，这样不对。
- **程序按规则抽取**（2026-10-18 定）：把各知识库 TODO 文档里没勾的 `- [ ]` 原样列出，一个知识库一组。
  先上线看效果，再决定要不要换成 agent（AI）归纳、去重、排序。
- **入口在搜索页**：搜索历史改成点进搜索框才弹出；平时搜索框下面的空白处显示这份清单。
- **只读**：每条能跳到对应的文档看前因后果；勾掉回 web 端做。手机阅读页保持只读，以后真有频繁需要再定。
- 已知条件：文档已经记录"是否有没勾的任务"（`has_incomplete_tasks`），文档列表接口可以按它筛选，
  不用全量扫描；calendar 块里的 `[ ]` 写在代码块中，不算任务。
- **实时算**：规则抽取很便宜，打开搜索页时实时算，不用每天定时生成、也不用单独存一份；这样 web 端刚勾掉的，手机上马上就看不到了。
  以后换成 agent 整理，再改成每天定时生成。
- **只算空的 `[ ]`**：`[>]` 之类的其他标记都不算没做完。
- **不折叠**：这些都是手动加的，数量不会膨胀到需要折叠。
- **实现**（2026-10-18）：不加接口。手机端用文档列表接口按 `has_incomplete_tasks == true` 取文档，
  只留根目录（`folder_path` 为空、不是子文档）里标题是 `TODO` 的（不区分大小写，带 `.md` 也算），
  再用 web 端同一套任务解析（`extractTasks`，跳过代码块）挑出空的 `[ ]`。每次打开搜索页都重新取。
  一个知识库一行（书架顺序），下面列出它的待办，点一下打开那篇 TODO；隐藏的知识库不算。

## 4. 整理现有的视图和布局，评估手机端支持哪些

现状（2026-10-18）：

| 类型 | 是什么 | 手机端现在 |
|---|---|---|
| Markdown 文档 | 普通文档 | 正常渲染 |
| HTML 文档 | 整页 HTML | 正常渲染 |
| PDF 文档 | PDF 附件 | 交给 Safari 自带的阅读器打开 |
| VIEW 文档 · 相册（Gallery） | 按范围实时列出子文档的卡片墙 | 占位卡片 |
| VIEW 文档 · 日历布局 | 按日期属性把文档铺到月历上 | 占位卡片 |
| VIEW 文档 · 说明文本 | 视图里的一段 Markdown | 随视图一起占位 |
| `calendar` 代码块 | 打卡日历（已由计划取代） | 占位卡片 |
| `kanban` 代码块 | 看板 | 占位卡片 |
| `grid` 代码块 | 卡片网格 | 占位卡片 |
| `mermaid` 代码块 | 流程图等 | 正常渲染 |
| draw.io 图 | 带源码的 SVG 图片 | 按图片显示 |
| 加密块（`toucan-secret`） | 加密内容 | 占位卡片 |

- 要做的四种，按这个顺序：相册 > 日历布局 > 看板、卡片网格（只读简化版）。都只读，用来浏览。
- calendar 块已经有计划替代，优先级最低；加密块暂不在手机上解密。
- `sheets` 表格已经彻底下线，以后也不会再启用，不在评估范围内。
- 这条和二期候选里的"常用视图只读预览"（[mobile-reader.md](mobile-reader.md) §11 第 2 条）合并考虑。

## 5. "我的"页面自定义

- **设置收进右上角**：现有的设置项（账号、字号、深色模式、添加到主屏幕、退出登录）收进右上角按钮，
  "我的"这一页留给自定义项目。计划设置不放进来，留在计划页。
- **自定义项目**在设置里配置，每项包括：图标、标题、备注、关联的 Markdown 文档。
  例：💰 · 年度理财计划 · "配置 7.7w，risk 5000，2026 年底到期" · 关联理财计划文档。点开进关联文档。
- **存在服务器上**：跟着账号走，换设备也在。
- **排序**：在设置里拖动排序，用成熟的拖拽库（`@dnd-kit`，2026-10-18 同意加这个依赖）。
- **渲染样式**可选，三期至少支持：多行条状（标题一行、备注另起一行）和单行条状（标题和备注同一行）。
- **实现**（2026-10-18）：
  - 存成用户设置 `ME_ITEMS`（`UserSetting.MeItemsSetting`），每次保存整份列表；服务端校验 id 唯一、标题必填、长度上限、最多 50 项。
  - 页面：`/me` 显示项目，右上角进 `/me/settings`；`/me/item/:id` 编辑，`new` 新建。编辑页点"完成"才保存，
    没填完的新项目不会出现在"我的"页上；删除前确认。
  - 没有关联文档的项目只显示，不能点。
- **分组和多篇关联**（2026-10-18，按讨论里的方案 A）：
  - 布局学 iOS 设置 / 微信：一组一张圆角卡片，组内各项用细线分隔，组名是卡片上方的灰色小字。
    不属于任何分组的项目排最前面，不带标题。
  - 分组存在 `MeItemsSetting.groups`（id、名称，顺序就是显示顺序），项目用 `group` 指向分组 id；
    指向已删除分组的项目算作未分组。最多 20 组。
  - 设置页按分组显示，拖动只在同一组内调整顺序；换分组在项目编辑页的"分组"里选。分组的"⋯"菜单可以重命名、
    上移/下移、删除（删除后组内项目移到未分组，不会被删）。
  - 项目可以关联多篇文档（`memos`，最多 20 篇，按添加顺序）。在"我的"页点一项：只关联一篇就直接打开，
    关联多篇就先弹出列表选一篇。原来的单篇字段 `memo` 已废弃，旧数据读取时当作只关联了这一篇。
  - 待办同样改成可关联多篇（`Todo.memos`）。数据库迁移 `0.30/27__planner_todo_memo_names.sql` 把 `memo_name`
    换成 JSON 数组 `memo_names`，并迁移已有的关联。
- 待定：备注里的数字要不要以后从关联文档自动取。

- **知识库加星、书架只显示加星的知识库**：讨论过，不做。书架照旧显示全部知识库，
  只是把封面改小成一行 3 个（2026-10-17 已改）。
