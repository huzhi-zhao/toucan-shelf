# 手机端阅读（Mobile Reader）

给手机 Safari 用的只读阅读端。界面独立于 web 端重新设计，目标只有一个：
**在手机上读知识库，要最顺、最像原生 App**。它不是 web 端的响应式适配，
也不是原生 App。

演示原型：<https://toucan-app.huzhi.dev>（演示数据、假登录，不连后端）。
实施方案待写，届时放在 `../design/` 下。

## 1. 定位与范围

- **只读**：不提供任何写操作。
- **平台**：手机 Safari（iOS 18 及以上为验收基线）。不做原生 App，不上应用商店。
  支持"添加到主屏幕"，从主屏幕打开时没有地址栏，体验最接近 App。
- **一期范围**：登录、书架（含最近阅读）、层级目录、搜索、文档阅读。

**一期明确不做**：编辑、评论、表情回应、历史版本、分享、归档视图、设置、
管理后台、附件库、通知、离线阅读、SSO 登录。
"共享给我的知识库"单独分组**无限延后**。

## 2. 入口与域名

**独立子域名 `toucan-app.huzhi.dev`**，不放在主站路径下。

电脑上也可以直接用这个手机端（2026-10-18 定）：浏览器打开同一个地址即可，宽屏下居中限宽显示；
计划等手机端功能不做 web 端兼容。

- 页面和接口都由**同一个后端**提供：手机端的页面随 web 端一起打包进后端，
  该子域名的 nginx 把页面导航改写到手机端入口，接口请求（Connect RPC、`/api/v1`、
  附件 `/file`）原样转发。对浏览器来说，页面和接口同源。
- 同源带来三件事，都不需要改后端：
  - refresh token cookie 没有设置 Domain，只属于当前主机，会落在
    `toucan-app.huzhi.dev` 下，续期照常工作。
  - 附件服务支持用 refresh cookie 认证，私有图片可以直接加载。
  - CORS 检查的是 Origin 和请求 Host 是否一致，所以 nginx 转发时必须保留原始 Host
    （`proxy_set_header Host $host`）。
- **约束**：
  - `toucan-app.huzhi.dev` 不能绑定为公开站点的自定义域名。前端服务会按 Host
    查找公开站点，绑定后请求会被当成站点访问。
  - 手机端和主站的登录态互不相通，各自登录。

**和主站之间的跳转**：
- 一期不做"手机打开主站链接自动跳到手机版"。
- 手机端需要引导去电脑端的地方（见 §7 占位卡片），给出主站的文档地址
  `https://toucan.huzhi.dev/memos/{uid}`。

## 3. 登录

- 只做用户名和密码登录，沿用 `SignIn` / `RefreshToken` / `SignOut`，不改认证。
- 如果实例关闭了密码登录（`disallow_password_auth`），登录页提示
  "当前实例已关闭密码登录，手机端暂不支持"。
- 必须登录才能使用，不支持游客访问公开文档。
- 登录有效期沿用服务端的 refresh token 设置。
- iOS 上主屏幕 App 和 Safari 的 cookie 是分开存的，从主屏幕打开需要单独登录一次。
  这是系统行为，不做处理。
- 退出登录在"我的"页右上角的设置里（三期起，见 [mobile-phase3.md](mobile-phase3.md) §5）。

## 4. 书架

- 数据来自 `ListWorkspaces(show_hidden=false)`：
  - 不显示隐藏的知识库，也不提供"显示已隐藏"的开关。
  - 别人共享给我的知识库和自己的混排，不加区分。
- 顺序和封面与 web 端一致：按 `display_order`、再按创建时间排序；
  封面用知识库设置的颜色或图片。
- **两种视图二选一**：封面视图（两列书封）或列表视图，用户自己切换，
  选择记在本机。
- **最近阅读**（一期纳入）：
  - 书架顶部横向列出最近打开的文档，最多 8 篇，点击直接进入文档。
  - 只存在手机本地，不和 web 端的"上次打开"同步。
  - 打开时如果文档已删除或没有权限，就从列表里移除。

## 5. 层级目录

- **逐层下钻**：一层一页，点文件夹进入下一层，返回回到上一层。不做树形展开。
- 每一层的排序**和 web 端完全一致**：遵循文件夹的 `sort_field` / `sort_order`
  及其继承规则，手机端不自己另排。
- 显示内容：
  - 文件夹：名称、下属文档数。
  - 文档：图标、标题、更新时间。
  - 空文件夹照常显示。
- 不显示归档文档，子文档也不进目录（与 web 端一致）。
- 目录数据用 `GetWorkspaceTree` 一次取整棵树，按知识库缓存。
  一期不针对大知识库做分页，上千篇的知识库要实测。
- 从下级返回时，恢复到离开时的滚动位置。
- 不同类型的文档：
  - Markdown：正常阅读（§7）。
  - HTML：沿用现有的 iframe 预览。
  - PDF：交给 Safari 自带的 PDF 查看器打开。
  - VIEW：显示占位卡片。

## 6. 搜索

- 一期只做**全局搜索**（`RagService.Search`，`global = true`），
  不提供"在本知识库内搜索"。
- **按下键盘上的"搜索"键才发请求**，不做边输入边搜。RAG 搜索可能会调用向量模型，
  逐字搜索又慢又费钱。
- 每条结果显示：所属知识库和路径、图标、标题、内容片段。
  用接口返回的 `highlights` 高亮命中的词。
- 搜索结果中的子文档和隐藏知识库，以服务端的过滤结果为准，手机端不另外处理。
- 搜索框为空时显示最近搜索，存在手机本地。

## 7. 文档阅读

**渲染器和 web 端是同一份代码**（见 §9），手机端不另写一份。

- **页头**：所在知识库和路径、文档图标和标题、更新时间。
  子文档额外显示"属于《父文档》"，可以点击跳转。
- **导航栏**：
  - 返回按钮。
  - 往下滚动后，标题收进导航栏。
  - 右侧两个按钮：目录（列出二、三级标题，点击跳转）、阅读设置。
  - 导航栏下方有阅读进度条。
- **占位卡片**：以下内容在手机端不渲染，显示"请在电脑端查看"的卡片，
  并提供"复制电脑端链接"：
  看板、表格（sheets）、日历、卡片网格、加密块、受限密钥块、VIEW 文档里的日历布局。
  - VIEW 文档的相册和说明文本已经可以只读预览（2026-10-19，见 [mobile-phase3.md](mobile-phase3.md) §4）。
  - Mermaid 图和文档嵌入先尝试直接用渲染器显示，效果不行再改为占位。
  - draw.io 图本身是一张 SVG 图片，直接按图片显示。
  - 文档开头的属性（frontmatter）面板不显示。
- **链接**：
  - 文档之间的链接（包括跨知识库的）跳到手机端对应的文档页。
  - 页内锚点链接定位到对应位置。
  - 外部链接在新标签页打开。
- **子文档**：文末的 References 区块列出子文档，点击进入。
- **图片和附件**：图片可以点开全屏查看，支持双指缩放；其他附件点击后下载或预览。
- **阅读设置**：
  - 字号 15–22px，行距分紧凑、标准、宽松三档。
  - 设置记在本机，和 web 端的阅读密度设置互不影响。
  - 深色模式跟随系统。
- **不显示**：评论、表情回应、历史版本、分享入口。

## 8. 体验标准

"最像原生"的具体要求：

- **页面转场**：
  - 进入下一级页面时，新页面从右侧推入；点应用内的返回按钮时，反向退出。
  - 用 Safari 边缘侧滑返回时，动画完全交给浏览器，应用不再叠加一层。
  - 系统开启"减弱动态效果"时不播放转场。
- **滚动**：
  - 阅读页使用整页滚动，这样 Safari 的工具栏能自动收起，点顶部状态栏也能回到顶部。
  - 列表页沿用组件库默认的滚动方式。
- **布局**：适配刘海和底部安全区，视口高度用 `dvh`。
  输入框字号不小于 16px，避免 Safari 聚焦时自动放大页面。
- **首屏速度**：首次打开时下载的资源，压缩后不超过 300 KB。
  重的渲染依赖（表格、图表、公式等）按需加载。
- **浏览器支持**：
  - iOS Safari 18 及以上为验收基线。
  - 更旧的版本可以用，但没有转场动画。
  - Android 浏览器尽力兼容，不作为验收项。

## 9. 已定的实现约束

以下几条是选型时定下的，实施方案必须遵守：

- **和 web 端同仓库、同构建**：在 `web/` 里新增第二个入口，共用接口客户端、
  登录续期、React Query hooks 和文档渲染器 `MemoContent`。
  手机端的页面、布局和组件全部独立，不复用 web 端的界面组件。
- **渲染器只维护一份**：手机端需要的差异（占位卡片、链接跳转目标）通过开关和
  Context 注入实现。现有的公开站点（`components/BlogSite/`）已经用同样的方式复用了渲染器。
- **组件库用 Konsta UI v5**：它基于 Tailwind 4，提供 iOS 风格组件，不接管路由。
  - 不用 Ionic：Ionic 9 只支持 React Router 6，而渲染器依赖 React Router 7。
  - 不用 Framework7：它有自己的路由，同样和渲染器冲突。
  - 两者的页面栈手势还会和 Safari 的侧滑返回冲突。
- **认证不改**：同源部署（§2）就是为了这一点。
