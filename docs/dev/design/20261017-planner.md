# 计划与打卡工具：实施方案

需求见 [../requirements/planner-and-check-in.md](../requirements/planner-and-check-in.md)。
本篇回答"怎么落地、分几步、每步怎么验收"。

## 1. 总体结构

```
store/migration/sqlite/0.30/24__planner.sql   四张新表（LATEST.sql 同步）
store/planner.go、store/db/sqlite/planner.go   存储层
proto/api/v1/planner_service.proto             PlannerService
server/router/api/v1/planner_service.go        接口实现
web/src/hooks/usePlannerQueries.ts             React Query hooks
web/src/mobile/pages/planner/                  计划页、待办详情、习惯管理、导入
web/src/mobile/lib/planner.ts                  纯逻辑：状态、分组排序、日历数据映射、导入转换
```

- 和知识库同库，但不碰 `memo`、`workspace` 等任何现有表，也不加外键。
- 所有接口都要登录，数据按 `creator_id` 归属，只能读写自己的。不改 `acl_config.go`。
- web 端本期不做页面，只有手机端入口。

## 2. 表结构

```sql
planner_habit     (id, uid, creator_id, name, position, archived, created_ts, updated_ts)
planner_check_in  (id, creator_id, habit_id, date, note, created_ts, updated_ts)
                  UNIQUE(habit_id, date)
planner_todo      (id, uid, creator_id, title, date, status, closed_overdue, closed_ts,
                   cancel_reason, important, tag, note, memo_name, url, created_ts, updated_ts)
planner_note      (id, uid, creator_id, date, content, created_ts, updated_ts)
```

- `date` 一律是 `YYYY-MM-DD` 文本，按手机本地日期，服务端不做时区换算。
  待办的 `date` 可以为空字符串（没有日期）。
- 打卡一个习惯一天最多一条（`UNIQUE(habit_id, date)`），和 calendar 块的行为一致。
- 待办 `status` 只存 `active` / `done` / `cancelled`。"已过期"不落库，由客户端按日期算。
- `closed_overdue`：关闭那一刻日期是否已过。服务端算，但"今天"由客户端在请求里带上
  （`local_date`），因为"一天"按手机本地时间划分。
- 备忘表叫 `planner_note`，避开现有的 `memo`（知识库文档）。
- `memo_name` 存关联文档的资源名 `memos/{uid}`，只是一个引用，文档删了也不级联。

## 3. 接口（PlannerService）

| RPC | 用途 |
|---|---|
| `ListHabits` / `CreateHabit` / `UpdateHabit` | 习惯列表与管理（改名、排序、停用） |
| `ListPlannerEntries(start_date, end_date)` | 日历一个月的数据：区间内的打卡、待办、备忘 |
| `ListOpenTodos` | 所有进行中的待办（待办清单、"今天"格子里的过期待办） |
| `SetCheckIn` / `DeleteCheckIn` | 打卡（带备注）/ 取消打卡 |
| `CreateTodo` / `UpdateTodo` / `DeleteTodo` | 待办增删改；`UpdateTodo` 用 field mask |
| `CreatePlannerNote` / `UpdatePlannerNote` / `DeletePlannerNote` | 备忘增删改 |
| `ImportPlanner` | 一次性导入，见 §6 |

**待办状态的规则在服务端执行**：
- 关闭（`done` / `cancelled`）时必须带 `local_date`；写入 `closed_ts`，并算出 `closed_overdue`。
- 取消必须有 `cancel_reason`，否则 `INVALID_ARGUMENT`。
- 重新打开（回到 `active`）清空 `closed_ts`、`closed_overdue` 和 `cancel_reason`。

## 4. 手机端页面

- **入口**：底部 Tab 在"书架"右边加"计划"（`/plan`）。
- **计划页**（`/plan`）：
  - 上：直接复用 web 的 `CalendarMonthGrid`（月历、彩色打卡圆点、任务方点、筛选）。
    数据从 `ListPlannerEntries` 映射成它要的 `CalendarItem`，日历和 calendar 块长得一样。
  - 中：选中那天的打卡、待办、备忘。打卡用习惯标签一点即打；点已打卡的标签弹出备注框，可写备注或取消打卡；
    待办点圆圈完成，点标题进详情；"+待办" / "+备忘"（待办一行一条）。今天那格额外列出所有过期待办。
  - 下：待办清单，所有进行中的待办按日期升序（过期的自然在最前、标红），没有日期的排最后。
- **待办详情**（`/plan/todo/:uid`）：标题、日期、重要、标签、备注、关联文档（用全局搜索选，点了进阅读页）、
  外部链接；底部是"完成"和"取消"（取消要填原因），已关闭的显示"重新打开"。
- **设置**（计划页右上角）：一周从哪天开始（默认跟随实例设置，存本机）、
  允许修改最近几天（默认 7，存本机）、习惯管理（新建、改名、停用）、导入日历数据。
- 修改历史的限制只在客户端拦（和 calendar 块一样，它是防误触，不是权限）：
  超过 N 天的日期，打卡和备忘只读；待办不受限制。
- 日历下方的"周X开始 ⇄"可以临时切换一周起始日（只在本次打开有效），默认值在设置里改。

## 5. 数据映射到日历

`CalendarMonthGrid` 吃的是 calendar 块的解析结果。映射规则（`lib/planner.ts`）：
- 打卡 → `{ isEvent: true, text: 习惯名, comment: 备注 }`，`events` 是未停用的习惯名，按 `position`。
- 待办 → `{ marker, text }`：进行中 `" "`、完成 `"x"`、取消 `"-"`。
- 备忘 → `{ text }`（没有 marker，就是 calendar 块的纯文本条目）。

## 6. 导入

- 入口在"计划设置 → 导入日历数据"：粘贴整段 calendar 块，先预览各类数量，确认后导入。
- 解析直接用现有的 `parseCalendarBlock`，转换规则见需求 §2.6，在客户端算好，
  一次 `ImportPlanner` 调用写入（一个事务）。
- **只能导入到空的计划**：已经有任何习惯、打卡、待办或备忘时，`ImportPlanner` 返回
  `FAILED_PRECONDITION`，防止重复导入。
- 打卡里引用了 `events:` 之外的名字时，按名字新建习惯，排在最后。

| 步骤 | 内容 | 验收 |

## 8. 实现备注

- `CalendarMonthGrid` 只在挂载时用 `events` 初始化圆点筛选。计划页的习惯是异步加载的，
  所以给它加了 `key={events}`，习惯变了就重新挂载，否则所有圆点一开始都被筛掉。
- 待办详情的文本字段失焦即存。每次保存都会重新拉取待办，只重置值真的变了的字段，
  不然正在另一个框里输入的内容会被冲掉。
- `buf.gen.yaml` 的插件没有锁版本，最新的 connect-go 会生成 `connectrpc.com/connect/v2`。
  这次生成用的是和仓库现有产物一致的版本：connectrpc/go v1.19.1、protocolbuffers/go v1.36.12、
  grpc/go v1.6.2、grpc-gateway v2.29.0、bufbuild/es v2.16.0；其他产物的无关漂移已还原。
- 用户删除时，计划数据随之删除（个人数据，不转移给别人）。
