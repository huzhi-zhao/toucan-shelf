# 附件

**一句话**：附件是**只读语料**。它们被下载到本地，正是为了让你能**读**；
但你**永不编辑、永不删除、永不移动、永不上传**它们。

---

## 1. 附件是什么，存在哪

附件是挂在某篇文档（memo）上的上传文件：图片、音频、视频、PDF、EPUB、
以及任意非媒体文件。字节存在实例配置的存储后端（本地 / 数据库 / S3-兼容），
和文档正文是两套东西。

memogit 检出时，附件被下载到所属 workspace 的：

```
<workspace>/_attachments/<附件 uid>/<原始文件名>
```

- **单向下载**：`clone` 和 `pull` 把字节拉下来（本地已有未变化的副本则跳过）；
  **`push` 从不上传附件**。你改了 `_attachments/` 里的文件，改动既不会回传，
  也可能在下次 pull 时被覆盖——纯粹的损失。
- 附件**不是**知识库文档，没有 `memogit-id`，不在文档树里。

## 2. 正文里的附件引用

**内联引用（`![](...)`）memogit 刻意不改写**，保持服务器上的原样。
字节下载在 `_attachments/` 里，引用不动。

> **别为了"修好链接"去改写这些引用。** 那会让文件看起来被本地编辑，
> 制造假冲突（`.remote` 副本 + 需要人工合并），而且没有任何收益——
> 服务器端那个引用本来就是对的。

**为什么正文里没有 `![](clip.mp4)` 这种内联音视频**：Markdown 管线用
`rehype-sanitize`，会剥掉手写的 `<audio>` / `<video>` 标签。播放器来自**附件路径**，
不是自定义 Markdown 语法：媒体附件（图片/音频/视频）在预览时渲染在**文档底部**、
带真正可播放的播放器；非媒体附件按文件名列成链接。

编辑器里的行为差异（了解即可，你不参与）：**粘贴**媒体 → 上传并在**光标处**插入
站内 `![](…)` 引用；**工具栏 + → 媒体** → 上传后放进**附件区**（不内联）。
非媒体文件一律进附件区。媒体单文件上限 10 MB。

## 3. 什么时候你**应该**读附件

附件被下载下来就是给你用的。以下情况主动去读：

- 用户让你总结、提取、引用、核对某篇文档所依赖的 **PDF / 图片 / 文档类附件**内容。
- 文档是 **PDF 文档**（`*.pdf.md`）——本地那个 `.pdf.md` 只是引用桩，**没有可编辑正文**，
  真正的内容在 `_attachments/<uid>/xxx.pdf` 里。要理解这篇"文档"讲什么，
  **必须去读那份 PDF 字节**。
- 正文里的内联图片引用指向的图，是理解上下文所必需的（图表、截图、示意图）。
- 需要交叉引用附件内容与正文是否一致时。

读的时候用你正常的文件读取能力（PDF、图片都能直接读）。**读是安全的、被鼓励的。**

## 4. 什么时候你**绝不**碰附件

| 动作 | 为什么不行 |
|------|-----------|
| 编辑 `_attachments/` 下的文件 | 单向下载，改动不回传，下次 pull 可能被覆盖 |
| 删除 `_attachments/` 下的文件 | 同上；且这不是"删除服务器附件"的正确方式，只是本地自残 |
| 移动/重命名附件目录 | 目录名是附件 uid，是索引，不是给人看的名字 |
| 编辑 `*.pdf.md` 引用桩 | 生成物，push 忽略它，改它不产生任何效果 |
| 试图"上传"附件 | 未实现（见 `memogit.md` 的限制章节）。需要加附件请让用户在 app 里做 |
| 帮用户"清理没用的附件" | 你看不到全部引用关系（评论、其他文档、分享链接都可能引用），删了不可逆 |

用户要求删附件或换附件时，**告诉他在 app 里操作**，不要自己动本地文件。

## 5. PDF 与 EPUB 的边界

- **PDF 是一种 doc_type**，但由上传的文件字节支撑。本地是 `.pdf.md` 桩 + `_attachments/`
  里的真实 PDF。在 app 里它用 pdf.js 查看器渲染，支持文本层选中、六色高亮/下划线、
  评论侧栏、文本提取。
- **EPUB 不是 doc_type**，就是一个普通附件（`application/epub+zip`）。
  在附件预览页会打开一个 e-reader（翻页/连续滚动、字体、背景、目录、书内批注）。
  阅读外观按书**存在服务端**、跨设备跟随；阅读位置按书缓存。
- 两者的**批注/评论都不在文件字节里**——是所属 memo 的子 comment memo
  （PDF 用页码 + 文本引用锚定，EPUB 用 CFI 锚定）。所以你读到的 PDF/EPUB 字节
  **看不到任何高亮和评论**，而你也无法通过改字节去影响它们。

## 6. 存储与访问控制（背景知识，不需要你操作）

- S3 存储走 **memos 域名代理**，不下发原始预签名 URL：上传和读取都经过服务端签名转发。
  好处是网络隔离、权限统一在 memos 自己的会话模型里、URL 可缓存/走 CDN。
- 附件的可访问性**跟随所属文档的可见性**（PUBLIC 匿名可读 / PROTECTED 需登录 /
  PRIVATE 仅创建者；未挂文档的附件仅创建者可见；归档文档的附件同样收紧）。
- 数据库备份**不含附件**——备份只覆盖 SQLite 数据库文件本身。
  用户问"备份了吗"时不要把附件算进去。
